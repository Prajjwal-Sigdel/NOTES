COURSE BIG PICTURE (UNIT 4 CONTEXT)
-----------------------------------
	Unit 4 is the hardware-interface heart of the subject. It explains how microprocessor buses
	communicate with memory and peripherals, how address decoding selects devices, and how
	parallel/serial interfaces are built using 8255 and 8251. It then introduces DMA and 8237A,
	which offload data transfer from CPU. This unit is highly practical and directly connects
	theory to real hardware design, debugging, and system-integration interview questions.

║ TOPIC 4.1: BUS STRUCTURE                                                                   ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Bus structure in microprocessor systems

	B. Definition
		Bus structure is the organized set of shared communication lines and timing methods used
		to transfer address, data, and control information among CPU, memory, and I/O devices.

	C. Why this topic matters
		It defines how all hardware blocks communicate in a system.
		Most interfacing errors come from poor bus understanding.

	D. Core theory
		Bus structure determines data transfer correctness, speed, and expandability. CPU places
		address and control on bus; selected device responds with/accepts data. Timing method may
		be synchronous (clock-driven fixed timing) or asynchronous (handshake-driven variable timing).
		A robust bus structure must avoid contention, maintain valid timing windows, and support
		multiple devices with predictable selection logic. In exam answers, explain not just lines,
		but also timing discipline and why it matters for practical interfacing reliability.

	E. Microtopic Breakdown
		E0. Definitions
			• Synchronous bus: Transfer events tied to common clock edges.
			• Asynchronous bus: Transfer controlled by request/acknowledge handshakes.
			• Bus contention: Multiple devices driving bus simultaneously.
			• Throughput: Effective data transferred per time.
			• Wait state: Extra cycles inserted for slower devices.

		E1. Synchronous vs Asynchronous Table
		┌─────────────────────┬──────────────────────────────────┬────────────────────────────────┐
		│ Parameter           │ Synchronous Bus                  │ Asynchronous Bus               │
		├─────────────────────┼──────────────────────────────────┼────────────────────────────────┤
		│ Timing control      │ Common clock                     │ Handshake signals              │
		│ Speed predictability│ High                             │ Depends on device response     │
		│ Design complexity   │ Lower logic complexity           │ Higher control complexity      │
		│ Device flexibility  │ Best for similar-speed devices   │ Better for mixed-speed devices │
		└─────────────────────┴──────────────────────────────────┴────────────────────────────────┘

		E2. Intuitive Representation Layer
			• Simple words: Synchronous = everyone follows same bell; asynchronous = turn-by-turn reply.
			• Analogy: Classroom bell system vs person-to-person conversation confirmation.
			• Exam thinking: timing source + pros/cons + use-case.

	F. 10-Mark Answer Framework
		• Define bus structure.
		• Explain synchronous and asynchronous models.
		• Add comparison table.
		• Mention reliability/speed implications.
		• Conclude with interfacing relevance.

	G. Likely questions
		1) Explain synchronous and asynchronous bus structures.
		2) Compare synchronous and asynchronous bus with examples.
		3) Why do mixed-speed systems prefer asynchronous signaling?

	H. Quick revision bullets
		• Bus structure = communication backbone.
		• Synchronous uses fixed clock.
		• Asynchronous uses handshake.
		• Wait states handle slow devices.
		• Correct timing prevents data corruption.

	I. Common mistakes
		• Assuming asynchronous always slower.
		• Ignoring handshake signal role.
		• Not mentioning bus contention issues.

	J. Visual Layout Elements
		Timing cue:
		Sync : CLK -> fixed transfer slots
		Async: REQ -> ACK -> transfer
		Graph cue:
		Device speed variation ↑ => asynchronous suitability ↑

	Practical lab linkage
		Observe fixed-cycle vs wait-state insertion using emulator traces.

	Real-life example
		Industrial controller backplanes often mix fast CPU and slower I/O modules.

	Troubleshooting scenario
		If intermittent data errors occur, inspect timing alignment/handshake completion.

║ TOPIC 4.2: MEMORY DEVICE CLASSIFICATION AND HIERARCHY                                      ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Memory device classification and hierarchy

	B. Definition
		Memory hierarchy is the layered organization of storage devices by speed, capacity, cost,
		and proximity to CPU to balance performance and affordability.

	C. Why this topic matters
		Interfacing decisions depend on memory type and speed.
		Exam questions often ask hierarchy trade-offs.

	D. Core theory
		Memory hierarchy ranges from fastest/smallest (registers, cache) to slower/larger
		(main memory, secondary storage). In 8085-oriented systems, RAM, ROM, EPROM, EEPROM,
		and flash-like concepts are discussed in terms of volatility, rewrite capability,
		and application role. Design must match memory type to requirement: program storage,
		runtime data, calibration constants, and persistent logs. In exam answers, include
		speed-cost-capacity trade-off and one practical memory-map planning statement.

	E. Microtopic Breakdown
		E0. Definitions
			• Volatile memory: Loses data when power is off.
			• Non-volatile memory: Retains data without power.
			• ROM family: Program storage-oriented memory types.
			• RAM: Read/write working memory.
			• Access time: Delay from request to valid data.

		E1. Hierarchy Table
		┌─────────────────────┬──────────────┬──────────────┬───────────────┐
		│ Level               │ Speed        │ Cost/bit     │ Capacity      │
		├─────────────────────┼──────────────┼──────────────┼───────────────┤
		│ Registers           │ Highest      │ Highest      │ Lowest        │
		│ Cache               │ Very high    │ High         │ Low           │
		│ Main Memory (RAM)   │ Medium-high  │ Medium       │ Medium        │
		│ Secondary Storage   │ Lower        │ Lower        │ Very high     │
		└─────────────────────┴──────────────┴──────────────┴───────────────┘

		E2. Intuitive Representation Layer
			• Simple words: Closest memory is fastest but smallest.
			• Analogy: Desk notes (fast) vs library archive (large but slower).
			• Exam thinking: speed-cost-capacity triangle.

	F. 10-Mark Answer Framework
		• Define memory hierarchy.
		• Classify volatile/non-volatile types.
		• Explain trade-off table.
		• Add interfacing relevance statement.
		• Conclude with system design balance.

	G. Likely questions
		1) Explain memory hierarchy with suitable table.
		2) Differentiate RAM and ROM families.
		3) Why is memory hierarchy necessary in computer systems?

	H. Quick revision bullets
		• Faster memory is costlier per bit.
		• Volatile vs non-volatile is key classification.
		• RAM for runtime, ROM for firmware.
		• Hierarchy balances performance and cost.
		• Memory map planning is practical skill.

	I. Common mistakes
		• Confusing EEPROM and EPROM behavior.
		• Ignoring write endurance constraints.
		• Writing hierarchy without trade-off explanation.

	J. Visual Layout Elements
		Hierarchy ladder:
		Registers -> Cache -> RAM -> Secondary Storage
		Graph cue:
		Capacity ↑ => speed ↓ (general trend)

	Practical lab linkage
		Classify memory components on a trainer kit memory map.

	Real-life example
		Firmware stored in ROM, runtime variables in RAM in appliance controllers.

	Troubleshooting scenario
		If system loses configuration on reboot, verify non-volatile storage usage.

║ TOPIC 4.3: INTERFACING I/O AND MEMORY                                                      ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Interfacing I/O and memory with microprocessor

	B. Definition
		Interfacing is the hardware and signal-level design process used to connect CPU with
		memory and peripheral devices through address decoding and control logic.

	C. Why this topic matters
		This is a core practical topic for design and troubleshooting.
		Most hardware viva questions are from this section.

	D. Core theory
		Interfacing requires correct device selection, valid read/write control timing, and
		compatible data bus connection. Address decoding logic generates chip-select signals
		for target memory/I/O devices. Decoding can be unique/full (no alias overlap) or
		non-unique/partial (multiple addresses map same device). Designers must choose between
		I/O-mapped and memory-mapped I/O based on instruction set usage, address consumption,
		and complexity. In exam answers, always include decoding purpose + mapping style comparison.

	E. Microtopic Breakdown
		E0. Definitions
			• Address decoding: Logic to generate device-select from address lines.
			• Unique decoding: One address range selects one device only.
			• Non-unique decoding: Aliasing due to partial address usage.
			• I/O mapped I/O: Separate I/O address space and IN/OUT instructions.
			• Memory-mapped I/O: I/O treated as memory address locations.

		E1. 4.3.1 / 4.3.2 / 4.3.3 Comparison Table
		┌─────────────────────────┬───────────────────────────────────────┬──────────────────────────────────────┐
		│ Method                  │ Advantage                             │ Limitation                           │
		├─────────────────────────┼───────────────────────────────────────┼──────────────────────────────────────┤
		│ Full/Unique decoding    │ No alias conflict, precise mapping    │ More logic hardware                  │
		│ Partial/Non-unique      │ Simpler and cheaper                   │ Address aliasing possible            │
		│ I/O mapped I/O          │ Saves memory address space            │ Limited I/O instruction style        │
		│ Memory-mapped I/O       │ Full memory instructions usable       │ Consumes memory address range        │
		└─────────────────────────┴───────────────────────────────────────┴──────────────────────────────────────┘

		E2. 4.3.4 I/O Address Decoding (8085)
			Definition:
				Selecting I/O ports using address lines and IO/M̅ control context.
			5-line explanation:
				8085 uses IN/OUT instructions for port operations in I/O-mapped mode.
				Port decoder activates CS for targeted peripheral.
				RD̅/WR̅ combine with IO/M̅ to produce I/O read/write controls.
				Correct port mapping avoids collision among peripherals.
				Exam diagrams should show address->decoder->chip-select path.

		E3. 4.3.5 Memory Address Decoding (8085)
			Definition:
				Selecting RAM/ROM blocks using higher address lines and decoding logic.
			5-line explanation:
				Memory devices are mapped in 64KB space using CS generation.
				Decoder output enables one memory chip at a time.
				Lower lines index location within selected chip.
				RD̅ and WR̅ control read/write access windows.
				Good mapping separates ROM boot zone and RAM working zone.

		E4. Intuitive Representation Layer
			• Simple words: Decoding is “who should respond” logic.
			• Analogy: Doorbell panel where only selected flat rings.
			• Exam thinking: address lines -> decoder -> chip select -> data transfer.

	F. 10-Mark Answer Framework
		• Define interfacing and address decoding.
		• Explain unique vs non-unique decoding.
		• Compare I/O-mapped and memory-mapped I/O.
		• Add 8085 decoding examples.
		• Conclude with hardware reliability impact.

	G. Likely questions
		1) Explain address decoding with unique and non-unique methods.
		2) Differentiate I/O-mapped and memory-mapped I/O.
		3) Explain I/O and memory address decoding in 8085.

	H. Quick revision bullets
		• Decoding selects intended device.
		• Full decode avoids aliasing.
		• I/O-mapped saves memory space.
		• Memory-mapped provides instruction flexibility.
		• Correct CS logic is critical.

	I. Common mistakes
		• Mixing IO/M̅ context in memory cycles.
		• Ignoring aliasing in partial decode.
		• Missing CS generation path in diagram.

	J. Visual Layout Elements
		Decode flow:
		Address Lines -> Decoder -> CS -> Device Enable -> RD̅/WR̅ Action
		Graph cue:
		Decode completeness ↑ => address conflict risk ↓

	Practical lab linkage
		Design a small decoder circuit for RAM + ROM + one output port.

	Real-life example
		Industrial PLC cards use decoder logic to map multiple sensor/output modules.

	Troubleshooting scenario
		If two devices respond together, check partial decoding/CS overlap.

║ TOPIC 4.4: PARALLEL INTERFACE AND 8255 PPI                                                 ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Parallel interface modes and Intel 8255 PPI architecture

	B. Definition
		Parallel interfacing is data transfer using multiple lines simultaneously; 8255 is a
		programmable peripheral interface chip providing configurable parallel ports and handshaking.

	C. Why this topic matters
		8255 is a classical and highly testable interfacing IC.
		It appears frequently in architecture + mode + control-word exam questions.

	D. Core theory
		8255 provides three 8-bit ports (A, B, C) grouped for flexible I/O operation. It supports
		simple I/O and handshaking-based modes for reliable peripheral communication. Control word
		register configures direction and mode of ports. Group A and Group B can operate in
		different modes simultaneously. Port C bits are often used for handshake/status signals.
		In exam answers, include architecture block, mode summary, and control-word interpretation.

	E. Microtopic Breakdown
		E0. 4.4.1 Modes Definitions
			• Simple I/O: Basic input/output without handshake.
			• Strobe I/O: Transfer synchronized by strobe signal.
			• Single handshaking: One-direction handshake control.
			• Double handshaking: Two-way coordination for robust transfer.

		E1. 4.4.2 8255 Architecture Definitions
			• Port A, Port B, Port C: Parallel data/status lines.
			• Group A: Port A + upper Port C bits.
			• Group B: Port B + lower Port C bits.
			• Control Register: Writes mode and direction configuration.

		E2. 8255 Mode Table
		┌───────────────────────┬──────────────────────────────────────────────────────────────┐
		│ Mode                  │ Characteristics                                              │
		├───────────────────────┼──────────────────────────────────────────────────────────────┤
		│ Mode 0                │ Simple input/output                                          │
		│ Mode 1                │ Strobed/handshaked input/output                              │
		│ Mode 2 (Group A)      │ Bidirectional bus mode with handshake                        │
		└───────────────────────┴──────────────────────────────────────────────────────────────┘

		E2.1 8255 Control Word Essentials
			• I/O mode uses control register with D7=1.
			• Group A selects Mode 0/1/2; Group B selects Mode 0/1.
			• Port C can be split into PC upper and PC lower for control/handshake usage.
			• BSR mode uses D7=0 to set/reset individual Port C bits.

		E2.2 Solved Control-Word Example (from provided style)
			Requirement:
			Port A = input, Port B = output,
			Port C Lower = input, Port C Upper = output,
			Group A Mode 0, Group B Mode 1.
			Derived control word (textbook-style):
			10010101B = 95H

		E2.3 BSR Mode Example Values
			• Set PC7  : 00001111B = 0FH
			• Set PC3  : 00000111B = 07H
			• Reset PC0: 00000000B = 00H
			• Reset PC2: 00000100B = 04H

		Note:
			BSR acts on Port C bits and does not disturb Port A/Port B I/O mode settings.

		E3. Intuitive Representation Layer
			• Simple words: 8255 is a configurable port-expansion manager.
			• Analogy: Reception desk with three windows and a signaling panel.
			• Exam thinking: ports + groups + mode + control word.

	F. 10-Mark Answer Framework
		• Define parallel interface and 8255.
		• Draw/explain 8255 block architecture.
		• Explain operating modes.
		• Describe control-word significance.
		• Conclude with practical I/O expansion use.

	G. Likely questions
		1) Explain architecture and modes of 8255 PPI.
		2) Differentiate 8255 Mode 0, Mode 1, and Mode 2.
		3) Explain role of Port C in handshaking.

	H. Quick revision bullets
		• 8255 has Port A, B, C.
		• Group A/B separation is important.
		• Port C supports control/handshake bits.
		• Control word configures direction and mode.
		• Widely used for parallel peripheral interfacing.

	I. Common mistakes
		• Treating all ports as always data-only.
		• Confusing mode assignments per group.
		• Ignoring control-word bit significance.

	J. Visual Layout Elements
		8255 block cue:
		[CPU Bus] -> [Control Reg] -> [Group A: Port A + PC upper]
		                           -> [Group B: Port B + PC lower]
		Graph cue:
		Handshake robustness ↑ => transfer error probability ↓

	Practical lab linkage
		Configure 8255 Mode 0 output for LED and Mode 1 input for switch bank.

	Real-life example
		Parallel keypad-scanner and display controller commonly use 8255-style interfacing.

	Troubleshooting scenario
		If port not responding, verify control word and CS/RD̅/WR̅ timing.

║ TOPIC 4.5: SERIAL INTERFACE AND 8251 USART                                                 ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Serial interfacing, transmission types, and Intel 8251 USART

	B. Definition
		Serial interfacing transmits data bit-by-bit over limited lines; 8251 USART is a
		programmable serial communication interface supporting synchronous/asynchronous modes.

	C. Why this topic matters
		Serial communication is fundamental in practical embedded and communication systems.
		8251 concepts are frequently asked in interface architecture questions.

	D. Core theory
		Serial communication reduces wiring and supports longer-distance communication compared
		to parallel links. In asynchronous mode, start/stop bits frame data without shared clock;
		in synchronous mode, sender and receiver share timing reference for efficient transfer.
		8251 USART manages transmit/receive logic, status reporting, and mode/command control.
		Correct initialization sequence is critical before data exchange begins. In exam answers,
		include transmission type comparison and block-level role of 8251 elements.

	E. Microtopic Breakdown
		E0. 4.5.1 Transmission Definitions
			• Synchronous: Clock-aligned serial transfer.
			• Asynchronous: Framed data with start/stop bits.
			• Baud rate: Symbol/bit rate per second in serial links.
			• Framing: Data packaging method for receiver interpretation.

		E1. 4.5.2 8251 USART Definitions
			• Mode register: Selects serial mode parameters.
			• Command register: Enables Tx/Rx and control features.
			• Status register: Indicates ready/error conditions.
			• Tx/Rx buffers: Hold outgoing/incoming data.

		E1.1 Block-Level Functional Signals (exam-ready list)
			• Data bus buffer: 8-bit bidirectional interface with CPU data bus.
			• Read/Write logic: RESET, CLK, WR̅, RD̅, C/D, CS̅.
			• Modem control lines: DSR, DTR, CTS, RTS.
			• Transmit section: TXD, TXRDY, TXE, TXC.
			• Receive section: RXD, RXRDY, RXC, SYNDET/BD.

		E1.2 8251 Control Words
			• Mode Instruction:
			  selects synchronous/asynchronous mode, character length, parity, stop-bit, baud factor.
			• Command Word:
			  enables transmitter/receiver, error reset, RTS/DTR handling, break-related control.
			• Status Word:
			  provides Tx ready/empty, Rx ready, parity/framing/overrun errors and status bits.

		Initialization sequence (important):
			Reset -> Write Mode Instruction -> (sync chars if synchronous) -> Write Command Word.

		E2. Sync vs Async Table
		┌─────────────────────┬──────────────────────────────────┬──────────────────────────────┐
		│ Parameter           │ Synchronous                      │ Asynchronous                 │
		├─────────────────────┼──────────────────────────────────┼──────────────────────────────┤
		│ Clock requirement   │ Shared clock                     │ No shared clock              │
		│ Overhead            │ Lower framing overhead           │ Start/stop bit overhead      │
		│ Implementation      │ More timing coordination         │ Simpler point-to-point       │
		│ Typical use         │ High-speed coordinated links     │ UART-like general serial I/O │
		└─────────────────────┴──────────────────────────────────┴──────────────────────────────┘

		E3. Intuitive Representation Layer
			• Simple words: Serial sends one bit at a time in sequence.
			• Analogy: One-lane road with ordered vehicles instead of multi-lane burst.
			• Exam thinking: mode type + framing/clock + 8251 register roles.

	F. 10-Mark Answer Framework
		• Define serial interface and 8251.
		• Compare synchronous vs asynchronous transfer.
		• Explain 8251 architecture/register roles.
		• Mention initialization and status-based transfer.
		• Conclude with communication-system relevance.

	G. Likely questions
		1) Differentiate synchronous and asynchronous serial transmission.
		2) Explain architecture and working of 8251 USART.
		3) Why is initialization required before USART data transfer?

	H. Quick revision bullets
		• Serial saves wiring lines.
		• Async uses start/stop framing.
		• Sync uses shared clock.
		• 8251 has mode/command/status controls.
		• Proper configuration is mandatory.

	I. Common mistakes
		• Confusing baud rate with byte rate.
		• Skipping mode setup before transmit.
		• Ignoring status readiness checks.

	J. Visual Layout Elements
		Serial frame cue (async): [Start][D0..D7][Parity?][Stop]
		Graph cue:
		Wire count ↓ => serial preference ↑

	Practical lab linkage
		Configure emulator UART-like channel and send/receive test bytes.

	Real-life example
		Microcontroller-to-PC debug console communication follows asynchronous serial concepts.

	Troubleshooting scenario
		If garbled characters appear, verify baud rate and frame format settings.

║ TOPIC 4.6: DMA AND INTEL 8237A DMA CONTROLLER                                              ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Direct Memory Access (DMA) and Intel 8237A controller

	B. Definition
		DMA is a data transfer technique where peripherals transfer data directly to/from memory
		without continuous CPU intervention; 8237A is a programmable controller managing this process.

	C. Why this topic matters
		DMA is critical for high-speed transfer efficiency.
		It is a common theory + architecture + signal-sequence exam topic.

	D. Core theory
		In programmed I/O, CPU handles each transfer, causing overhead. DMA reduces this by letting
		a controller request bus ownership, transfer data in block/burst/cycle-steal style, and then
		release control. 8237A provides multiple channels, request/acknowledge signaling, address/
		count management, and mode configuration. CPU involvement is limited to setup and completion
		handling, improving throughput for bulk data transfer. In exam answers, explain sequence:
		request -> grant -> transfer -> release -> resume CPU normal operation.

	E. Microtopic Breakdown
		E0. Definitions
			• DREQ: Peripheral request to DMA controller.
			• DACK: DMA channel acknowledgement.
			• HRQ/HLDA: Bus request/hold acknowledge with CPU.
			• Cycle steal: DMA takes bus for short intermittent transfers.
			• Burst mode: DMA transfers block before releasing bus.

		E1. 8237A Elements Table
		┌─────────────────────┬──────────────────────────────────────────────────────────────────┐
		│ Element             │ Function                                                         │
		├─────────────────────┼──────────────────────────────────────────────────────────────────┤
		│ DMA Channels        │ Independent transfer paths for peripherals                       │
		│ Address Register    │ Current memory address for transfer                              │
		│ Count Register      │ Remaining bytes/words count                                      │
		│ Mode Register       │ Select transfer mode and channel behavior                        │
		│ Status/Control      │ Reports completion and controls operation                        │
		└─────────────────────┴──────────────────────────────────────────────────────────────────┘

		E1.1 Channels and Register Mapping (concept)
			• Four channels: CH0, CH1, CH2, CH3.
			• Each channel has:
			  - Memory Address Register (start/current memory location)
			  - Count Register (remaining transfer count)
			• Each channel can support up to 64 KB transfer in basic textbook framing.

		E1.2 Signal Groups (explicit)
			Signals with peripherals:
			• DREQ0-DREQ3 (DMA request)
			• DACK0-DACK3 (DMA acknowledge)
			Signals with CPU/system bus:
			• HRQ, HLDA
			• AEN, ADSTB
			• MEMR̅, MEMW̅
			• A3-A0 internal register addressing lines

		E1.3 DMA Transfer Sequence (stepwise)
			1) Peripheral raises DREQ.
			2) 8237 raises HRQ to CPU.
			3) CPU completes current cycle and responds HLDA.
			4) 8237 asserts DACK and performs transfer.
			5) On terminal count/end condition, DMA releases bus.
			6) CPU resumes normal bus control.

		E1.4 8237 Transfer Modes
			• Single Transfer Mode: one transfer per request service.
			• Block Transfer Mode: continuous transfer until terminal count/EOP.
			• Demand Transfer Mode: continues while DREQ remains active.
			• Cascade Mode: expands system using additional cascaded DMA controllers.

		E2. Intuitive Representation Layer
			• Simple words: DMA is a shortcut path that avoids CPU handling each byte.
			• Analogy: Dedicated cargo conveyor instead of manager carrying every packet.
			• Exam thinking: explain bus handover sequence clearly.

	F. 10-Mark Answer Framework
		• Define DMA and need.
		• Explain DMA transfer sequence.
		• Describe 8237A architecture/elements.
		• Compare DMA with programmed I/O.
		• Conclude with throughput advantage.

	G. Likely questions
		1) Explain DMA process with suitable flow sequence.
		2) Explain architecture and functions of Intel 8237A.
		3) Differentiate programmed I/O and DMA transfer.

	H. Quick revision bullets
		• DMA reduces CPU transfer overhead.
		• 8237A supports multi-channel transfer.
		• Bus handover uses HRQ/HLDA handshake.
		• DREQ/DACK identify requesting peripheral.
		• Best for high-volume data movement.

	I. Common mistakes
		• Treating DMA as zero CPU involvement always.
		• Ignoring setup/programming phase.
		• Missing bus release/resume stage.

	J. Visual Layout Elements
		DMA sequence flow:
		Peripheral DREQ -> 8237 HRQ -> CPU HLDA -> DMA transfer -> bus release
		Graph cue:
		Data volume ↑ => DMA benefit ↑

	Practical lab linkage
		Simulate block data transfer with DMA mode and compare CPU utilization.

	Real-life example
		Audio/video streaming controllers rely on DMA-like bulk transfer.

	Troubleshooting scenario
		If DMA transfer stalls, inspect channel enable, terminal count, and request signals.

║ TOPIC 4.7: 8254 PROGRAMMABLE INTERVAL TIMER (PIT)                                         ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Intel 8254 PIT architecture, control word, and operating modes

	B. Definition
		8254 PIT is a programmable timer/counter IC with three independent 16-bit counters,
		used for precise delays, periodic interrupts, square-wave generation, and event counting.

	C. Why this topic matters
		8254 is a standard exam topic for architecture, control word derivation, and timing problems.
		It is directly useful in delay generation and real-time control design.

	D. Core theory
		8254 has data bus buffer, read/write control logic, a control word register, and counters
		Counter0/Counter1/Counter2. Counter/control register selection is by A1/A0 lines.
		A control word defines counter select, read/write format, mode (0-5), and binary/BCD option.
		Each counter can be loaded with count value and then operated according to configured mode.
		In exam answers, include control-word field interpretation and one solved count example.

	E. Microtopic Breakdown
		E0. Counter/Control Register Select Table
		┌────┬────┬────────────────────┐
		│ A1 │ A0 │ Selection          │
		├────┼────┼────────────────────┤
		│ 0  │ 0  │ Counter 0          │
		│ 0  │ 1  │ Counter 1          │
		│ 1  │ 0  │ Counter 2          │
		│ 1  │ 1  │ Control Register   │
		└────┴────┴────────────────────┘

		E1. 8254 Control Word (field idea)
			SC1 SC0 | RW1 RW0 | M2 M1 M0 | BCD
			• SC selects counter
			• RW selects LSB/MSB access format
			• M selects mode 0-5
			• BCD selects BCD/binary counting

		E2. Modes 0-5 (short exam notes)
			• Mode 0: Interrupt on terminal count.
			• Mode 1: Hardware retriggerable one-shot.
			• Mode 2: Rate generator.
			• Mode 3: Square wave generator.
			• Mode 4: Software-triggered strobe.
			• Mode 5: Hardware-triggered strobe.

		E3. Solved Example-1 (textbook-style)
			Task: BCD counter, Mode 2, Counter 0, 16-bit count.
			Control word: 00110101B = 35H

		E4. Solved Example-2 (1 KHz square wave using Counter 1)
			Given f_clk = 2 MHz, desired f_out = 1 KHz (Mode 3)
			Count = f_clk / f_out = 2000000 / 1000 = 2000 (07D0H)
			Common textbook sample control word used: 77H
			Programming pattern:
				MVI A,77H
				OUT 83H
				MVI A,D0H
				OUT 81H
				MVI A,07H
				OUT 81H
				RET

		E5. Solved Example-3 (50 us pulse width using Counter 0)
			Given f_clk = 2 MHz, T = 50 us (Mode 1)
			Count = T / T_clk = 50 us / 0.5 us = 100 (0064H)
			Textbook control word: 35H
			Programming pattern:
				MVI A,35H
				OUT 83H
				MVI A,64H
				OUT 80H
				MVI A,00H
				OUT 80H
				RET

		Note:
			Some manuals/examples use slightly different address maps or count orders (LSB/MSB)
			based on interface design. Always follow the lab kit mapping provided in question.

	F. Likely questions
		1) Explain architecture and control word format of 8254 PIT.
		2) Explain modes 0-5 of 8254 with key use-case.
		3) Derive control word/count for square-wave or delay generation.

	G. Quick revision bullets
		• 8254 has three independent 16-bit counters.
		• A1/A0 select counter or control register.
		• Modes 2 and 3 are most common in periodic signal generation.
		• Control word decides counter, mode, access format, and BCD/binary.
		• Always compute count from clock and required output timing.
