COURSE BIG PICTURE (UNIT 5 CONTEXT)
-----------------------------------
	Unit 5 explains how processors respond to urgent events using interrupts. Instead of waiting
	for software polling loops, CPU can pause current execution, service high-priority requests,
	and resume normal flow safely. This unit combines architecture, control instructions,
	priority logic, vector handling, ISR design, and programmable interrupt controller concepts.
	It is highly exam-oriented and practically essential for real-time and embedded systems.

║ TOPIC 5.1: INTERRUPT, SOURCES, AND CLASSIFICATION                                          ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Interrupt concept, sources, and classification

	B. Definition
		An interrupt is an event signal that temporarily suspends normal CPU program execution,
		transfers control to an interrupt service routine, and returns to the original program
		after servicing the event.

	C. Why this topic matters
		Interrupts are the backbone of responsive embedded systems.
		Most real-time devices rely on interrupt-driven processing.

	D. Core theory
		Without interrupts, CPU must continuously poll devices, wasting cycles and increasing
		latency. Interrupt-driven design allows immediate response to critical events like external
		signal change, timer overflow, or communication completion. Interrupts can be hardware or
		software, maskable or non-maskable, vectored or non-vectored. Correct classification helps
		designers choose handling strategy and priority policies. In exam answers, define types,
		give one example for each, and explain why interrupts outperform simple polling loops.

	E. Microtopic Breakdown
		E0. Definitions
			• Hardware interrupt: Triggered by external/internal hardware events.
			• Software interrupt: Triggered by instruction (e.g., INT/RST).
			• Processor interrupt: Generated by CPU due to internal exception/error condition.
			• Maskable interrupt: Can be disabled by software control.
			• Non-maskable interrupt: Cannot be ignored; highest urgency.
			• Vectored interrupt: ISR address provided through predefined vector.

		E0.1 Three Interrupt Sources (explicit)
		┌─────────────────────┬──────────────────────────────────────────────────────────────────┐
		│ Source              │ Example                                                         │
		├─────────────────────┼──────────────────────────────────────────────────────────────────┤
		│ Processor Interrupt │ 8086 Type 0 (divide by zero)                                    │
		│ Software Interrupt  │ INT nnH (e.g., INT 21H)                                         │
		│ Hardware Interrupt  │ External request on NMI/INTR pins                               │
		└─────────────────────┴──────────────────────────────────────────────────────────────────┘

		E1. Classification Table
		┌───────────────────────┬───────────────────────────────────────────────────────────────┐
		│ Type                  │ Typical Meaning / Use                                         │
		├───────────────────────┼───────────────────────────────────────────────────────────────┤
		│ Hardware              │ External sensor/event service                                  │
		│ Software              │ Program-invoked service routine                                │
		│ Maskable              │ Normal configurable priority handling                           │
		│ Non-maskable          │ Emergency/critical response                                     │
		│ Vectored              │ Fast direct jump to known ISR address                           │
		└───────────────────────┴───────────────────────────────────────────────────────────────┘

		E2. Intuitive Representation Layer
			• Simple words: Interrupt is a “priority call” to CPU.
			• Analogy: Teacher pauses class to handle urgent fire alarm.
			• How to think in exam: event type -> urgency -> handling style.

	F. 10-Mark Answer Framework
		• Define interrupt and need.
		• Explain sources and classifications.
		• Compare polling vs interrupt approach.
		• Add real-time application example.
		• Conclude with responsiveness benefit.

	G. Likely questions
		1) Define interrupt and classify its types.
		2) Differentiate maskable and non-maskable interrupts.
		3) Why are interrupts preferred over polling?

	H. Quick revision bullets
		• Interrupt improves CPU efficiency.
		• Hardware/software interrupt distinction is basic.
		• Maskable can be disabled; non-maskable cannot.
		• Vectored interrupts reduce ISR lookup overhead.
		• Real-time systems depend on interrupt response.

	I. Common mistakes
		• Mixing software and hardware interrupt definitions.
		• Assuming all interrupts are maskable.
		• Ignoring ISR return-to-main-flow concept.

	J. Visual Layout Elements
		Event flow:
		[Normal Program] -> [Interrupt Event] -> [ISR] -> [Return]
		Graph cue:
		Event urgency ↑ => interrupt priority ↑

	Practical lab linkage
		Simulate external interrupt trigger and observe ISR execution.

	Real-life example
		Traffic signal emergency override (ambulance priority) is interrupt-like behavior.

	Troubleshooting scenario
		If event is missed, verify interrupt enable state and priority configuration.

║ TOPIC 5.2: INTERRUPT PROCESSING SEQUENCE IN 8085/8086                                      ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Interrupt processing sequence in 8085 and 8086

	B. Definition
		Interrupt processing sequence is the ordered CPU procedure for accepting interrupt,
		saving context, executing ISR, and restoring context to continue main program.

	C. Why this topic matters
		Sequence-based explanation is a common 10-mark exam question.
		Correct ISR design depends on understanding this flow.

	D. Core theory
		When an interrupt request is recognized, CPU completes current instruction, acknowledges
		the request, saves return address/state, and transfers control to ISR entry point.
		ISR executes required service, restores saved context, and returns using RETI/IRET-type
		logic depending on architecture context. 8085 and 8086 differ in details (flags handling,
		vector mechanisms), but fundamental concept remains same. In exams, always write stepwise
		sequence and mention context save/restore importance.

	E. Microtopic Breakdown
		E0. Sequence Definitions
			• Acknowledge: CPU confirms pending interrupt acceptance.
			• Context save: Preserve registers/flags/PC state before ISR logic.
			• Vector transfer: Load ISR target address.
			• Service phase: Execute interrupt-specific routine.
			• Return phase: Restore state and resume interrupted code.

		E1. Generic Sequence Table
		┌───────────────┬──────────────────────────────────────────────────────────────────────┐
		│ Step          │ Operation                                                            │
		├───────────────┼──────────────────────────────────────────────────────────────────────┤
		│ 1             │ Current instruction completes                                         │
		│ 2             │ Interrupt request checked and acknowledged                             │
		│ 3             │ Return context saved (PC/flags/etc.)                                  │
		│ 4             │ ISR address loaded (vectored/non-vectored mechanism)                  │
		│ 5             │ ISR executed                                                          │
		│ 6             │ Context restored and program resumed                                  │
		└───────────────┴──────────────────────────────────────────────────────────────────────┘

		E2. Intuitive Representation Layer
			• Simple words: Pause work, handle urgent task, then resume exactly from pause point.
			• Analogy: Bookmark current page before handling urgent call.
			• How to think in exam: accept -> save -> service -> restore -> continue.

	F. 10-Mark Answer Framework
		• Define interrupt sequence.
		• Write step-by-step flow.
		• Mention context and return logic.
		• Compare 8085/8086 conceptual similarities.
		• Conclude with reliability impact.

	G. Likely questions
		1) Explain interrupt processing sequence in 8085/8086.
		2) Why is context save/restore mandatory in ISR?
		3) What happens if ISR does not restore state properly?

	H. Quick revision bullets
		• CPU completes current instruction first.
		• Context save is mandatory.
		• ISR must be short and precise.
		• Return instruction restores normal flow.
		• Sequence errors cause unpredictable behavior.

	I. Common mistakes
		• Forgetting context push/pop.
		• Treating interrupt as immediate mid-instruction break.
		• Missing return mechanism details.

	J. Visual Layout Elements
		Flow graph:
		Program -> IRQ -> Save -> ISR -> Restore -> Program
		Graph cue:
		ISR complexity ↑ => latency risk ↑

	Practical lab linkage
		Implement timer interrupt routine and inspect return to main loop.

	Real-life example
		Keyboard keypress interrupt allows immediate character capture without polling loops.

	Troubleshooting scenario
		If main loop crashes after ISR, check stack/context restoration order.

║ TOPIC 5.3: INTERRUPT INSTRUCTIONS, PINS, PRIORITY, ISR, IVT, MULTIPLE HANDLING            ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Interrupt instructions and handling components in 8085/8086

	B. Definition
		Interrupt instructions and handling components are control elements (instructions, pins,
		priority rules, vector tables, service procedures) that govern how interrupts are accepted
		and serviced in microprocessor systems.

	C. Why this topic matters
		This section combines most exam-ready micro-level interrupt details.
		It directly supports coding, architecture, and troubleshooting questions.

	D. Core theory
		Interrupt control involves enable/disable instructions, prioritized interrupt pins,
		structured ISR procedures, and vector mechanisms for fast target addressing. In 8085,
		EI enables and DI disables maskable interrupts, while RST instructions provide software
		vector calls. Priority determines which interrupt is serviced first when multiple requests
		are pending. ISR should save context, service event, clear source condition, and return.
		IVT or fixed vector locations provide deterministic entry points for service routines.

	E. Microtopic Breakdown
		E0. 5.3 Interrupt Instruction Definitions
			• EI: Enable maskable interrupts.
			• DI: Disable maskable interrupts.
			• RST n: Restart/software vector interrupt invocation.
			• RETI/IRET concept: Return from interrupt service context.

		E1. 5.3.1 Interrupt Pins and Priorities (8085 focus)
			Definition:
				Interrupt input lines with defined urgency levels.
			Typical order (high to low): TRAP > RST7.5 > RST6.5 > RST5.5 > INTR
			5-line explanation:
				TRAP is non-maskable and highest priority for critical events.
				RST7.5/6.5/5.5 are maskable vectored lines.
				INTR is maskable non-vectored and needs external vector support.
				Priority logic prevents simultaneous-service conflict.
				Exam answers should state priority explicitly.

		E1.1 8085 Interrupt Vector Table (Hex)
		┌─────────────┬────────────────┬──────────────┬───────────────────────────┐
		│ Interrupt   │ Maskable?      │ Vectored?    │ Vector Address            │
		├─────────────┼────────────────┼──────────────┼───────────────────────────┤
		│ TRAP        │ No             │ Yes          │ 0024H                     │
		│ RST 7.5     │ Yes            │ Yes          │ 003CH                     │
		│ RST 6.5     │ Yes            │ Yes          │ 0034H                     │
		│ RST 5.5     │ Yes            │ Yes          │ 002CH                     │
		│ INTR        │ Yes            │ No           │ External vector required  │
		└─────────────┴────────────────┴──────────────┴───────────────────────────┘
		Note:
			RST 5.5/6.5/7.5 can be managed with SIM/RIM in addition to EI/DI context.

		E2. 5.3.2 Interrupt Service Procedure
			Definition:
				Well-defined routine that handles interrupt event then returns safely.
			5-line explanation:
				ISR should be short and deterministic. First save context,
				then execute minimal service logic, clear interrupt source,
				restore context, and return. Avoid long blocking loops in ISR.
				Poor ISR design increases latency and can miss further events.
				Exam answers must include save/restore steps.

		E3. 5.3.3 Interrupt Vector Table
			Definition:
				Memory table of ISR entry addresses for vectored interrupt handling.
			5-line explanation:
				Vector mechanism gives fixed or table-based ISR jump addresses.
				This reduces software overhead during interrupt dispatch.
				In architectures with IVT, each vector maps to service routine entry.
				Correct mapping is required for proper response behavior.
				Exam diagrams often include vector-to-ISR relation.

		E3.1 8086 IVT Structure (explicit)
			• 256 vectors located from 00000H to 003FFH (1024 bytes = 1 KB).
			• Each vector uses 4 bytes:
			  - first 2 bytes: IP (offset)
			  - next 2 bytes: CS (segment)
			• Vector address start = 4 x interrupt type number.

		E3.2 8086 Predefined Interrupt Types
			• Type 0: Divide by zero / divide error.
			• Type 1: Single-step (Trap Flag based debug mode).
			• Type 2: Non-maskable interrupt (NMI pin).
			• Type 3: Breakpoint (INT 3).
			• Type 4: Overflow (INTO-based handling when OF=1).

		E3.3 Priority of 8086 Interrupts (as textbook ordering)
		┌──────────────────────────────────────┬───────────┐
		│ Interrupt Class                      │ Priority  │
		├──────────────────────────────────────┼───────────┤
		│ Divide error / INT n / INTO          │ Highest   │
		│ NMI                                  │ Higher    │
		│ INTR                                 │ Lower     │
		│ Single step                          │ Lowest    │
		└──────────────────────────────────────┴───────────┘

		E4. 5.3.4 Multiple Interrupt Handling
			Definition:
				Method of servicing more than one interrupt source safely and predictably.
			5-line explanation:
				Multiple requests are handled by priority, masking, or nested strategy.
				Critical interrupts may preempt lower-priority handlers.
				Design must prevent starvation and stack overflow risk.
				Latency budgeting is important for real-time systems.
				In exam answers, mention priority resolution logic.

		E5. 5.3.4.1 Polled vs Vectored Interrupt
			Definition:
				Polled interrupt identifies source by software polling; vectored interrupt
				directly provides ISR address.
			5-line explanation:
				Polled approach is simpler hardware-wise but slower in response.
				Vectored approach is faster and deterministic but may need more support logic.
				Polled systems are acceptable for low event rate environments.
				Vectored methods suit high-performance or strict-latency designs.
				Exam answers should include speed vs complexity trade-off.

		E5.1 Vectored Interrupt Daisy-Chain Sequence (short)
			1) Devices assert interrupt request.
			2) CPU issues interrupt acknowledge.
			3) Higher-priority device captures acknowledge first.
			4) Device places vector address/data on bus.
			5) CPU jumps to ISR and services device.
			6) Acknowledge chain continues for remaining pending requests.

		E8. 8086 Interrupt Processing Flow (explicit stack context)
			• Complete current instruction.
			• Disable further maskable interrupts for protected entry sequence.
			• PUSH Flags, PUSH CS, PUSH IP.
			• Load ISR CS:IP from vector entry.
			• Execute ISR.
			• IRET restores IP, CS, Flags and resumes interrupted program.

		E6. Comparison Table
		┌───────────────────────┬────────────────────────────────────┬────────────────────────────┐
		│ Method                │ Advantage                          │ Limitation                 │
		├───────────────────────┼────────────────────────────────────┼────────────────────────────┤
		│ Polled                │ Simple implementation              │ Slower source identification│
		│ Vectored              │ Fast direct ISR dispatch           │ More architecture support  │
		└───────────────────────┴────────────────────────────────────┴────────────────────────────┘

		E7. Intuitive Representation Layer
			• Simple words: Interrupt control is traffic management for urgent events.
			• Analogy: Hospital triage prioritizes severe cases first.
			• How to think in exam: instruction + pin priority + ISR + return safety.

	F. 10-Mark Answer Framework
		• Define interrupt instruction/control ecosystem.
		• Explain EI/DI/RST roles.
		• Describe pin priorities and ISR sequence.
		• Add IVT and multiple-interrupt strategy.
		• Compare polled vs vectored.
		• Conclude with system reliability impact.

	G. Likely questions
		1) Explain EI, DI, and RST in 8085 interrupt control.
		2) Explain interrupt pins and priorities in 8085.
		3) Differentiate polled and vectored interrupt handling.

	H. Quick revision bullets
		• EI enables; DI disables maskable interrupts.
		• TRAP is highest priority and non-maskable.
		• ISR must save/restore context.
		• IVT enables deterministic routing.
		• Polled vs vectored = simplicity vs speed.

	I. Common mistakes
		• Forgetting to clear interrupt source in ISR.
		• Ignoring priority order in multiple requests.
		• Writing ISR without context preservation.

	J. Visual Layout Elements
		Priority ladder:
		TRAP > RST7.5 > RST6.5 > RST5.5 > INTR
		ISR flow:
		IRQ -> Save -> Service -> Clear -> Restore -> Return
		Graph cue:
		Interrupt load ↑ => need for priority discipline ↑

	Practical lab linkage
		Build two interrupt sources and verify priority-based servicing behavior.

	Real-life example
		Emergency stop switch should preempt normal sensor event handling.

	Troubleshooting scenario
		If repeated ISR triggering occurs, source-clearing logic is likely missing.

║ TOPIC 5.3.5: PROGRAMMABLE INTERRUPT CONTROLLER (PIC) INTEL 8259                           ║
╚════════════════════════════════════════════════════════════════════════════════════════════╝

	A. Topic Name
		Intel 8259 PIC and its architecture/features

	B. Definition
		Intel 8259 is a programmable interrupt controller that manages multiple interrupt inputs,
		prioritizes requests, and provides vectored interrupt service coordination with CPU.

	C. Why this topic matters
		8259 is a key interface IC in interrupt management architecture.
		It is frequently tested in block diagram and feature-based questions.

	D. Core theory
		As interrupt sources increase, direct CPU interrupt handling becomes complex. 8259 PIC
		aggregates interrupt lines, resolves priority, and supports vector generation. It can be
		configured for priority mode, masking, and cascading to handle more interrupt channels.
		Main internal functional ideas include interrupt request register, in-service tracking,
		and mask register control. In exam answers, describe request capture, priority resolve,
		vector dispatch, and end-of-interrupt handling sequence.

	E. Microtopic Breakdown
		E0. Definitions
			• IRR: Interrupt Request Register (pending requests).
			• ISR (in-service register in PIC context): Tracks active service line.
			• IMR: Interrupt Mask Register controls enabled requests.
			• Cascading: Expanding interrupt inputs using master-slave PIC arrangement.
			• EOI: End-of-interrupt command to clear in-service status.

		E0.1 Block-Level 8259A Functions
			• Data Bus Buffer: 8-bit bidirectional interface to CPU data bus.
			• Read/Write Control Logic: manages CS̅, RD̅, WR̅, A0, INTA̅ interactions.
			• Status Registers: IRR, ISR, IMR.
			• Priority Resolver: chooses highest-priority active request.
			• Cascade Buffer/Comparator: CAS2-CAS0 and SP/EN̅ support master/slave setup.

		E1. 8259 Feature Table
		┌─────────────────────────┬──────────────────────────────────────────────────────────────┐
		│ Feature                 │ Benefit                                                      │
		├─────────────────────────┼──────────────────────────────────────────────────────────────┤
		│ Priority resolver       │ Deterministic servicing order                               │
		│ Masking support         │ Selective interrupt enable/disable                           │
		│ Vector support          │ Faster ISR dispatch                                          │
		│ Cascading capability    │ More interrupt channels                                      │
		│ In-service tracking     │ Prevents conflict in nested/ongoing handling                 │
		└─────────────────────────┴──────────────────────────────────────────────────────────────┘

		E1.1 Common 8259A Operating Modes
			• Fully Nested Mode
			• Rotating Priority Mode (automatic/specific)
			• Special Mask Mode
			• Polled Mode

		E1.2 8259A Interfacing Signals (minimum list)
			• CPU side: INT -> INTR, INTA̅ <- INTA.
			• Control side: CS̅, RD̅, WR̅, A0.
			• Request side: IR0-IR7 for interrupt sources.
			• Cascade side: CAS2-CAS0 and SP/EN̅.

		E1.3 Handling More Than 8 Interrupts (example: 18 interrupts)
			• Use one master 8259A and two slave 8259A in cascade.
			• Set master with SP/EN̅=1 and slaves with SP/EN̅=0.
			• Connect each slave INT output to one IR input of master.
			• Connect CAS0-CAS2 master to CAS0-CAS2 of both slaves.
			• Connect master INT to CPU INTR and master INTA̅ to CPU INTA.
			• This configuration scales interrupt handling beyond 8 lines (e.g., 18 devices/sources).

		E2. Intuitive Representation Layer
			• Simple words: 8259 is a smart traffic controller for many interrupt roads.
			• Analogy: Airport control tower managing multiple landing requests.
			• How to think in exam: request capture -> priority -> vector -> service complete.

	F. 10-Mark Answer Framework
		• Define 8259 PIC.
		• Explain need for programmable interrupt management.
		• Describe major internal registers/blocks.
		• Explain priority and vector handling.
		• Mention cascading and EOI flow.
		• Conclude with scalable interrupt control benefit.

	G. Likely questions
		1) Explain architecture and working of Intel 8259 PIC.
		2) Why is PIC required in multi-interrupt systems?
		3) Explain masking and priority resolution in 8259.

	H. Quick revision bullets
		• 8259 manages multiple interrupts.
		• Priority resolver is key block.
		• Masking allows selective control.
		• Vector-based handling improves speed.
		• Cascading supports expansion.

	I. Common mistakes
		• Confusing CPU ISR with PIC ISR register context.
		• Ignoring EOI requirement.
		• Not explaining why PIC is needed at scale.

	J. Visual Layout Elements
		PIC flow:
		IR inputs -> IRR -> Priority Resolver -> Vector/INT -> CPU ACK -> ISR -> EOI
		Graph cue:
		Interrupt sources ↑ => PIC necessity ↑

	Practical lab linkage
		Simulate two interrupt levels through PIC model and verify servicing order.

	Real-life example
		Industrial automation panels with many sensors use centralized interrupt arbitration.

	Troubleshooting scenario
		If lower-priority interrupts never run, verify mask register and EOI handling.

QUICK REVISION (UNIT 5)
====================================================================================================
	• Interrupt = urgent event-driven control transfer.
	• Processing sequence: finish current instruction -> save -> ISR -> restore -> resume.
	• EI/DI control maskable interrupts.
	• TRAP is highest priority in 8085.
	• 8086 IVT: 256 vectors, 1 KB space, each vector = IP + CS.
	• 8086 predefined: Type 0 to Type 4 are high-yield exam points.
	• ISR must be short, deterministic, and context-safe.
	• Polled = simpler, vectored = faster.
	• 8259 provides scalable prioritized interrupt management.
